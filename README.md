# method-sync-v2

CLI над Java-бібліотекою біржового конектора. Людина перелічує в `registry.toml` уже реалізовані методи біржі;
інструмент знімає живу відповідь, звіряє з нею DTO (поля, яких бракує або які зайві) і енами (значення, яких
бракує), жене `claude -p` до зеленої перевірки і лишає правку некоміченою в робочій копії бібліотеки разом зі звітом.

Навіщо енами: енами бібліотеки «стійкі» — невідоме значення мовчки стає `UNKNOWN`, тож нове значення біржі не
ламає десеріалізацію, а тихо губиться. На 2026-09-29 `/fapi/v1/tradingSchedule` уже віддавав `FX`, якого в
`MarketType` не було (`docs/research.md`, R-011).

## Запуск

```bash
PYTHONPATH=src python3 -m method_sync --registry registry.toml --dry-run      # звірити, агента не кликати
PYTHONPATH=src python3 -m method_sync --registry registry.toml                # звірити і виправити
PYTHONPATH=src python3 -m method_sync --registry registry.toml --only /fapi/v1/tradingSchedule
```

Звіт — `runs/<метод>/report.md`, лог ітерацій і фікстура — поряд. Коди виходу: `0` усе зелене, `1` червоне,
`2` реєстр непридатний, `3` жива відповідь недоступна, `4` немає стандарту стилю бібліотеки.

Перевірка самого інструмента:

```bash
npm run test:run            # 221 юніт + 12 селф-тестів хука
npm run test:integration    # + справжній Java-раннер проти копії бібліотеки і живої біржі
npm run test:e2e            # CLI зі справжнім агентом по доказових сценаріях -> docs/qa/e2e-report.md
```

## Як будувалось

Проєкт вела фабрика [Project Factory](https://github.com/koldovsky/project-factory) 2.0.0 у Claude Code:
вимоги → специфікації OpenSpec → план слайсів → тести першими → реалізація → `review-gate` → архів, з гейтами G0–G4.
Попередня версія — method-sync v1 — дала вимоги, принципи й код-еталон. Хронологія рішень і рівнів довіри —
[`docs/autonomy-log.md`](docs/autonomy-log.md).

## Що вирішувала людина

Обсяг («не більше, ніж у method-sync, плюс енами»), принцип IX (невидимі константи енама не видаляються),
перехоплення винятку клієнта, waiver на coverage, план із 5 слайсів і потім швидкий шлях, усі 7 покращень
фабрики, правило ADR-0003 (блокують лише major/critical), заборона публікації. Повний перелік — у журналі.

## Чесно про те, чого немає

- Evals і `trajectory-eval` фабрики свідомо не робились (швидкий шлях).
- Слайс 1 заархівовано з доказом рецензії `clean: false`: третій раунд ішов за старою логікою воркфлоу.
- Coverage-ratchet — waiver (лише stdlib).
- Це знеособлений експорт робочого репо: пакет приватної бібліотеки замінено на `com.example`, email автора —
  на noreply GitHub, назви внутрішніх систем прибрано з усієї історії, хеші комітів у документах перемаплено.
  Сама бібліотека приватна, тож `npm run test:integration` і `npm run test:e2e` тут не відтворити — їхні
  записані прогони лежать у `docs/qa/e2e/` і `docs/qa/e2e-report.md`; `npm run test:run` іде без неї.
