## R1-01 [confirmed, major, correctness] Body with a lone surrogate escapes capture() as a raw UnicodeEncodeError and leaves the previous fixture empty (0 bytes)

- **Місце:** `src/method_sync/live.py:139`
- **Доказ:** `json.dumps(..., ensure_ascii=False, ...)` (lines 130-131) keeps a lone surrogate from a body such as `{"symbol": "BTC\ud800USDT"}`, which Python's json accepts. `fixture.write_text(text, encoding="utf-8")` then opens the file in 'w' mode, emptying it, before the encode fails with UnicodeEncodeError. The `except OSError` at line 140 does not catch that. Probe (local server, existing 38-byte fixture): `UnicodeEncodeError: 'utf-8' codec can't encode character '\ud800' ... surrogates not allowed` escaped capture(), and the fixture was left at 0 bytes. This breaks the design goal that no input defect leaves the modules as a fourth exception class (the CLI would print a traceback), and it wipes the previous run's evidence (principle II).
- **Пропозиція:** Encode before touching the filesystem. Do `data = text.encode("utf-8")` inside try/except UnicodeEncodeError and raise a typed error: LiveUnavailable (the body cannot be kept 'as is' in UTF-8) or FixtureWriteError. Then write the bytes to a temp file in the same directory and `os.replace` it, so no failure can empty an existing fixture. Add tests for body `{"s": "\ud800"}` (typed exception, old fixture unchanged byte for byte) and for the write branch of FixtureWriteError, e.g. `fixture.json` pre-created as a directory. That branch currently has no test.

## R1-02 [confirmed, major, correctness] The live-exchange unit test ties `npm run test:run` and CI to the exchange's HTTP state; its skip guard only checks TCP reachability

- **Місце:** `tests/live_test.py:872`
- **Доказ:** The only guard is `socket.create_connection(("fapi.binance.com", 443), timeout=5)`. Any HTTP-level refusal makes `live.capture(EXCHANGE, PREMIUM, args, self.runs)` (line 876) raise LiveUnavailable, and the test ERRORs instead of skipping. Examples: Binance's 451 for clients in restricted locations, 418/429 during rate-limit bans, 5xx during maintenance. `.github/workflows/ci.yml` runs `npm run test:run` on `ubuntu-latest`, and its own header says the layers needing a live exchange 'run locally'. Locally the test passed. I could not observe CI (no remote or run history), so a red CI from a 451 on GitHub runners is an expectation, not a verified fact.
- **Пропозиція:** Gate the class the same way as `LiteralTimeLimits` (e.g. `METHOD_SYNC_LIVE_EXCHANGE=1`, with a visible skip reason), or skip when `GITHUB_ACTIONS` is set. The real-exchange evidence already lives in smoke task 5.7 and the e2e harness.

## R1-03 [confirmed, minor, correctness] A timed-out worker thread keeps reading a slow body with no limit; the docstring says it stops on its own

- **Місце:** `src/method_sync/live.py:197`
- **Доказ:** The `_within_limit` docstring (line 165) says the socket gets the same timeout, so a stuck thread 'відпадає сам'. But the socket timeout applies per operation, so a server that keeps sending bytes slower than the limit keeps `response.read()` (line 197, no size cap) running. Probe: body dripped at 0.05 s/byte with `timeout=0.3` gave the verdict at 0.31 s, yet the 'method-sync live call' thread was still alive at 1, 3 and 6 s. In the CLI, every such method would leave a thread, an open socket and a growing buffer for the rest of the run.
- **Пропозиція:** Have the worker respect the deadline: read in chunks (`response.read(65536)`) in a loop that stops once `time.monotonic()` passes the deadline or an Event set by the main thread at the verdict, and cap the total size. Fix the docstring and the design D8 wording to match.

## R1-04 [confirmed, minor, correctness] NaN/Infinity in the body count as JSON and are written as bare tokens; TOML nan/inf in args are not turned into strings

- **Місце:** `src/method_sync/live.py:113`
- **Доказ:** `json.loads(raw)` accepts `NaN`/`Infinity` by default. `json.dumps(..., default=str)` (line 130) writes them back as bare tokens, because allow_nan=True and `default` never fires for floats. Probe: body `{"markPrice": NaN, "x": Infinity}` with `args = { limit = nan, cap = inf }` produced a fixture containing `"args": {"limit": NaN, "cap": Infinity}` and `"body": {"markPrice": NaN, ...}`, which a strict JSON parser rejects. This goes against FR-24 ('значення, якого JSON не представляє, — рядком') and FR-26 (a non-JSON body is unavailable).
- **Пропозиція:** Parse the body with `json.loads(raw, parse_constant=...)` that raises, and report it as LiveUnavailable('тіло не розбирається як JSON: ...'). For args, convert non-finite floats to `str` before dumping, then dump with `allow_nan=False` so any leak fails loudly.

## R1-05 [confirmed, minor, correctness] A registry containing an integer over 4300 digits makes load() raise a raw ValueError instead of RegistryError

- **Місце:** `src/method_sync/registry.py:146`
- **Доказ:** `_parse` catches only `tomllib.TOMLDecodeError` and `RecursionError` around `tomllib.loads(text)`. tomllib does not wrap the int-max-str-digits error. Probe: `status = 111…` (5000 digits), or the same inside `args`, gave `ValueError: Exceeds the limit (4300 digits) for integer string conversion` out of `load()`. That contradicts the module docstring 'Назовні виходить лише `RegistryError`' (design D5), so the CLI would show a traceback. Invalid dates and deep nesting are already wrapped correctly.
- **Пропозиція:** Catch `ValueError` as well; TOMLDecodeError is a subclass of it, so `except (ValueError, RecursionError)` covers both. Raise `RegistryError(f"реєстр {shown} не розбирається як TOML: {error}") from error`, and add the 5000-digit case to `RegistryFile`.

## R1-06 [confirmed, minor, correctness] The 'immutable' Method and Registry can still be changed, and Method is unhashable

- **Місце:** `src/method_sync/registry.py:83`
- **Доказ:** The docstring (line 76) and design D1 promise that later stages cannot modify a Method. `frozen=True` only blocks reassigning attributes: `args: dict` and `Registry.methods: list` stay mutable and are the same objects tomllib returned. So `method.args["symbol"] = "X"` silently changes the URL and fixture a later stage builds. The generated `__hash__` hashes the dict, so `hash(Method(...))` raises `TypeError: unhashable type: 'dict'` (probe). That is a trap for later slices that group methods, e.g. FR-14 shared slug.
- **Пропозиція:** Either narrow the claim (document that only reassignment is blocked and Method cannot be hashed), or store a copy and make `methods` a tuple. That is a deliberate change to the two tests that pin `list`/`dict`, per the AGENTS test-first rule. If you use a read-only mapping such as MappingProxyType, convert it with `dict()` in `capture()`: `json.dumps(..., default=str)` would otherwise write it as the string "{'a': 1}" (verified).

## R1-07 [confirmed, minor, correctness] lib under a directory the process cannot enter is reported as missing

- **Місце:** `src/method_sync/registry.py:169`
- **Доказ:** In Python 3.14, `Path.exists()` returns False for any OSError, including PermissionError, so line 169 raises `цільової бібліотеки lib немає: …` for a directory that exists but cannot be reached. Probe: a real git repo at `locked/lib` with `chmod 0 locked` produced exactly that message. The path is named, but the reason sends the user looking for a missing directory instead of fixing permissions (NFR-11).
- **Пропозиція:** Call `os.stat(lib)` in a try. Map FileNotFoundError/NotADirectoryError to 'немає' and PermissionError to a 'lib недоступна: Permission denied' message, then check the directory with `stat.S_ISDIR`. Do the same for `.git`.

## R1-08 [confirmed, minor, security] After the NFR-4 verdict the worker thread keeps its socket open and reads an unbounded body for as long as the server drips bytes; the claim that it 'drops off by itself' is false

- **Місце:** `src/method_sync/live.py:197`
- **Доказ:** The server at base_url (or a man-in-the-middle on an http:// base_url) can hold one thread and one socket per method for the whole run by sending a byte more often than the socket timeout. _within_limit raises LiveUnavailable after join(timeout) (line 180) but never stops the worker. response.read() (line 197) has no size cap, and its timeout applies to each socket read, not the whole body, as the docstring itself says at lines 163-164. So the claim at lines 165-166 ('завислий потік відпадає сам') and in design.md D8 and Risks is wrong. Probe: Content-Length 100 MB, one byte every 0.2 s, fetch(timeout=0.5). The verdict came at 0.51 s, but the 'method-sync live call' thread was still alive and reading at 3 s, 6 s and 10 s, and ended only when the server stopped. From the code (not probed): a fast endless body also grows memory without limit, and the resulting MemoryError is re-raised untyped by `raise error` at line 186.
- **Пропозиція:** Enforce the deadline and a size cap inside the worker. Compute `deadline = time.monotonic() + timeout` once and read with `response.read1(65536)` in a loop (at most one socket read per call). Stop and close the response when the deadline passes or the total exceeds a cap, for example 32 MB, reported as LiveUnavailable 'тіло більше за …'. Fix the wording in the docstring and in D8/Risks. Add a test with a server that drips forever and assert the worker thread is gone shortly after the verdict (about the timeout plus one socket timeout).

## R1-09 [confirmed, minor, security] Server-controlled bytes reach the LiveUnavailable message unsanitised: terminal escapes, CR/LF and up to 64 KB through BadStatusLine, and ESC survives the 400-body excerpt

- **Місце:** `src/method_sync/live.py:232`
- **Доказ:** Design D11 says the CLI prints str(error) as is, and the server at base_url (a compromised endpoint, or a man-in-the-middle on an http:// base_url) controls part of that text. _client_reason returns str(cause) for any HTTPException, and http.client.BadStatusLine carries the raw status line: up to 65,536 characters decoded as ISO-8859-1, including CR/LF and C0/C1 control characters. _status_reason (line 211) collapses whitespace but keeps ESC and BEL. Probes against a local socket server: status line `\x1b]0;PWNED\x07\x1b[2J not-http` gave the reason '\x1b]0;PWNED\x07\x1b[2J not-http\r\n'; a 60,000-character status line gave str(error) of 60,056 characters; a 400 body with `\x1b[31m` and an OSC 8 hyperlink came through unchanged. Once add-run-cli prints this, a server can retitle or clear the terminal, disguise links, and break the one-line-per-method output.
- **Пропозиція:** Pass every string that comes from the server (the body excerpt and str(cause) for HTTPException subclasses) through one sanitiser: escape C0/C1 control characters and DEL (for example as \xNN), collapse the text to one line, and cap it at EXCERPT_CHARS followed by '…'. Add tests with ESC in a 400 body and with a garbage status line, asserting the reason is a single line with no \x1b and a bounded length.

## R1-10 [confirmed, major, spec-compliance] A 200 JSON body that parses but can't be encoded as UTF-8 escapes capture() as a raw UnicodeEncodeError and wipes the previous fixture

- **Місце:** `src/method_sync/live.py:139`
- **Доказ:** Spec FR-24 (live-capture delta, requirement 'Фікстура живої відповіді'): 'Невдалий запис — внутрішня помилка: код методу `1`, повідомлення називає шлях, прогін іде далі'. design.md Goals: 'Жодна вада входу не виходить із модулів іншим класом винятку, ніж три названі нижче: інакше CLI надрукує traceback.' What the code does: lines 130-131 call `json.dumps(..., ensure_ascii=False, ...)`, then line 139 calls `fixture.write_text(text, encoding="utf-8")`, and the handler around it catches only `OSError`. Probe: a local server returned 200 with `{"symbol":"\ud800"}`, which is valid JSON with a key, so it counts as available. A 36-byte fixture from an earlier run was already in place. `capture()` raised `UnicodeEncodeError: 'utf-8' codec can't encode character '\ud800' ... surrogates not allowed`, which is neither FixtureWriteError nor LiveUnavailable, and the old fixture was left at 0 bytes. The cause is that `write_text` opens the file with 'w' (truncating it) before it encodes the text. No test covers a body that parses but can't be encoded.
- **Пропозиція:** Serialize to bytes before touching the filesystem: `data = text.encode("utf-8")`, or use `ensure_ascii=True`, which escapes lone surrogates. Map `UnicodeEncodeError` to a typed error (FixtureWriteError, or LiveUnavailable 'тіло не кодується в UTF-8') before `mkdir`/open, then call `fixture.write_bytes(data)`. Add a test: body `{"symbol":"\ud800"}` gives a typed exception, and an existing fixture stays byte-for-byte the same.

## R1-11 [confirmed, major, spec-compliance] capture() can write outside runs/: slug '..' escapes to the tool root, and a symlinked runs/<slug> is followed

- **Місце:** `src/method_sync/live.py:132`
- **Доказ:** Spec FR-24: the tool 'MUST зберегти відповідь фікстурою `runs/<slug>/fixture.json` у `runs/` інструмента'. Constitution VII: 'Інструмент пише ЛИШЕ ... у власний `runs/`'. run-cli FR-91 (openspec/specs/run-cli/spec.md:261-273): 'Шлях звіряється після розкриття `..` і символьних посилань ... Запис поза коренями не виконується'. Its scenario makes `runs/fapi-v1-fundingRate` a symlink to `docs/` and requires that `docs/fixture.json` does not appear. What the code does: lines 132-141 build `directory = pathlib.Path(runs_dir) / slug_for(path)`, then run `mkdir` and `write_text` with no containment check. Probes with a local 200 server: path '/../' (slug '..') wrote `<runs_dir>/../fixture.json`, outside runs/. Paths '/' and '/./' both wrote `runs/fixture.json`, so every such method shares one file. With a symlink `runs/fapi-v1-fundingRate -> docs/`, the fixture was written to `docs/fixture.json`. The registry spec's 'Поза обсягом' only drops slug checks from registry validation; the location promise in FR-24 still holds. v1 has the same gap: `boundaries.assert_writable` exists but nothing calls it. `capture()` has no seam before the write, so slice 4 cannot enforce FR-91 for fixtures without reopening this module.
- **Пропозиція:** Check containment in capture() before `mkdir`/write: `target = directory.resolve()`, and require `target.parent == pathlib.Path(runs_dir).resolve()`; otherwise raise FixtureWriteError naming the resolved path. That meets FR-24 now and already satisfies FR-91's fixture scenario. Add tests for '/../', '/' and a symlinked slug directory. Otherwise, record in design.md that add-run-cli will change capture() for FR-91, and name '..'/'.'/'' slugs explicitly as out of scope in the spec.

## R1-14 [confirmed, minor, spec-compliance] After a timeout verdict the worker thread keeps running as long as the server drips bytes; design D8 says it ends on its own

- **Місце:** `src/method_sync/live.py:176`
- **Доказ:** design.md D8: 'Сокет отримує той самий `timeout`, тож завислий потік відпадає сам'. Risks section: 'Завислий daemon-потік живе до тайм-аута сокета'.
