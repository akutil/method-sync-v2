# Design — add-core

## Еталон

Код method-sync v1 (`/Users/akutil/humex/method-sync/src/method_sync/{verify,loop,agent,report,library,boundaries,__main__}.py`)
пройшов живі прогони на тій самій бібліотеці і є основою реалізації: структуру, імена, раннер і бриф беремо звідти.
v2 відрізняється лише там, де це кажуть специфікації цієї зміни:

| Що | v1 | v2 |
|---|---|---|
| Виняток клієнта в раннері | не перехоплювався, JVM висіла до таймауту (R-014) | перехоплюється: `client_error` у вердикті, звіряння йде далі, вердикт червоний |
| Енами | немає | енамні властивості верхнього рівня (значення, колекція, ключі мапи); живе значення перевіряється десеріалізацією Jackson з `READ_UNKNOWN_ENUM_VALUES_USING_DEFAULT_VALUE`; запасник поза звірянням; нове значення → червоно, агент дописує константу перед запасником; невидимі константи — у звіт, не видаляються (принцип IX) |
| Множина полів | інтроспекція серіалізації | властивості, у які Jackson десеріалізує (є мутатор) |
| Порядок переліків | `TreeSet` | за кодовими точками Unicode |
| Ранні зупинки CLI | модуль і стандарт після живого виклику | FR-22 → FR-20 → FR-21 до живого виклику; відсутній клас моделі — код 2 |
| Звіт | без енамів | + `enum_mismatch`, `enum_unseen`; ярлик compile — «команда перевірки не пройшла» |
| `--dry-run` | без логу ітерації | пише `iteration-1.log` |
| Помилки реєстру й живого виклику | часом traceback | типізовані `RegistryError`, `LiveUnavailable`, `FixtureWriteError` (слайс 1) → коди 2, 3, 1 |

## Рішення

- Сторонній світ у тестах — лише на межі (параметри `verify`, `agent`, `open_url`), як у v1; раннер проти справжньої
  бібліотеки ганяється в інтеграційному шарі (`METHOD_SYNC_LIVE=1`, копія `.sandbox/binancefutures`).
- Бриф і повідомлення українською, ідентифікатори англійською (NFR-13).
